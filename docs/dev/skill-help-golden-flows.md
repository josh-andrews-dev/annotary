- **The skill is the contract with agents:** it tells them to read through the CLI (never `*.annotary`), cite `tN "quote"` never line numbers, pull → edit outside → push, then answer each Thread it acted on like a colleague (what changed in which Version, or why not; a question gets an answer, not an edit; an unclear comment gets a question back) and resolve only what it fully addressed (S39-01; any Member with `comment` may resolve), guard with `--version N`, `wait` not poll, `--json` when parsing; the command table lists exactly the verbs/flags the golden flow exercises. Changing a verb's output shape or a flag the skill names means editing the skill (≤ 60 lines) *and* the goldens *and* checking `make token-report`. The keep-current hook is by version string only (`annotary --version` ≠ `metadata.version` ⇒ `skill install`) — Phase 2's harness plug-ins reuse the verb; no auto-update, no network.
- **`--help` is the reference** (story 149): literal templates, not clap's generated help, for the verbs the prototype documented; the rest stay clap-generated (they list the global flags themselves, which the templated ones leave to `TOP`). Usage errors are untouched (clap's `Usage:` line). The whole top-level help is measured in `tests/token-report.md` against the ceiling `crates/annotary/tests/token_report.rs` sets (the prototype's `--help` count in `PROTOTYPE` × 1.2, rounded up), so adding a `TOP` line near the ceiling requires cutting another.
- **Golden flows:** `95-agent-flow/agent.trycmd` is the spec's primary seam for the whole review loop — treat it as the end-to-end acceptance test: a change that alters any line of it must be a deliberate decision recorded in the ticket's report. It seeds the CLI prototype's scenario for real (Thread ids follow creation order, so the prototype's t4/t5/t6 became t6/t8/t4 — the shipped numbering is the truth), uses `-p agent` for the agent's `ANNOTARY_TOKEN` (the env path is S01-11), pulls with `--assets` so the agent's push re-uploads nothing and keeps the asset Thread anchored, and pins only the first row of `mentions` (cross-Document). After its push the agent answers @linter's question t8 with a plain `thread reply` (no edit, left open for the asker), the S39-01 behavior. `wake.sh` = the one place a trycmd golden runs two commands at once (`wait` parked + `act`), synced on the TTY `wait: watching` note exactly like `tests/cli_wait.rs`.
- **Decisions to keep:** `--dir` is the skills root (`DIR/annotary/SKILL.md`), never the skill folder itself; identical file ⇒ `unchanged`, differing ⇒ refused without `--force` (an older install never silently wins, a local edit is never clobbered); the committed source keeps the literal release version and a unit test pins it to the crate version (so a version bump without touching the skill fails `cargo test`); `.agents/skills/annotary/` is git-ignored; the token report is a golden of *normalized* output (ids → `k7q2m9xd`, ages → `4d`, cursors → 812/814, ISO → the prototype's) so the numbers are stable across runs; the ±20% band is against the prototype's numbers, not against the last run.

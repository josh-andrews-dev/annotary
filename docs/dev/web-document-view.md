# Web UI: Document view + list (ticket 10 — extend, don't rewrite)

Implementation notes, moved from the root `CLAUDE.md` on 2026-10-18 (read on demand; the
index is [README.md](README.md)). Extend them with the code they describe.

- **Files:** `server/listing.rs` (`GET /`), `server/view.rs` (`GET /d/{id}`, `GET /d/{id}/v/{n}`), `server/splice.rs`, `server/ui.rs` + `server/ui/app.css` + `server/ui/app.js`; routes sit in the `web_pages` router of `app.rs` (06's loopback-trust / login-redirect middleware: a bearer or the `cd_session` cookie signs in, a credential-less loopback browser becomes the founding owner while no password is set, else `303 /login?next=`); `AppState.titles` (display-title cache by `md_hash`). Errors on page routes come back as HTML (`ui::error_page`), never JSON. Every selector/id the pages own is namespaced `cd-` — the rendered Document keeps the bare element names and the renderer's few classes (`asset-missing`, `mermaid`, `language-x`, `footnotes`, …).
- **One response (spec 117/128):** `view::render_page` loads the Document, the Versions, the rendered HTML of the viewed Version (`render::ensure_html` — the stored blob, or the server's fallback render), the Threads (head: `Store::threads` status all, hidden excluded; older: `Store::threads_at(n)` — the time-slice), the Action log (`Store::actions`; the viewed Version's chip = the last Action *on that Version*), every Member (`ui::members_by_handle`), and splices the Threads **into the rendered HTML** (`splice::splice`): the Document-level strip under the title (after a leading `h1`, else first), one `.cd-strip[data-line]` per anchor line at the deepest block covering it (inside `li`/`td`/`th`/`blockquote`/`dd`/`dt`/`section`, after leaf blocks — `splice.rs` has the rules), the orphaned group last (`details.cd-orphaned`, closed). `#cd-data` carries `{id, name, vault, head, version, seq, me, threads:[{id, subject, status, line, end, quote, now, hash, ref, resolved, mine, occ}]}` for the script. Nothing on the page fetches Threads; the only request the script makes is `GET /api/v1/events?doc=ID` for the on-demand History panel (#cd-whatsnew) <!-- ---- ticket 11 ---- --> — plus, since ticket 11, the SSE subscription on that URL after the first layout, the mutations, the card fragment and the lazy head-Markdown read (see "Web UI: commenting") <!-- ---- end ticket 11 ---- -->.
- <!-- ---- ticket 15 ---- --> **Viewport-first rendering + deferred scripts (ticket 15):** the page is complete without the script, so (1) `ui::shell_ex` inlines `app.js` / `admin.js` as `<script type="module">` (deferred — the browser paints first; modules keep their order) and `app.js` waits one frame (`requestAnimationFrame` → `setTimeout(main)`) before its work, so the first paint never waits for it; (2) `app.css` puts `content-visibility: auto` (+ `contain-intrinsic-size: auto`) on the Document's top-level blocks and the Thread cards **from the 61st child of `.cd-doc` on** — the first 60 render in the first frame (a placeholder in view that grows after the first paint is a layout shift) — **except a block that contains a strip or precedes one** (`:has(.cd-strip)`, `:has(+ .cd-strip)`: the margin card aligns with the highlight inside it, and measuring a skipped block would force its layout); `layout()` re-runs on `contentvisibilityautostatechange` (capture on `.cd-doc`) when a card or block takes its real size. Keep these selectors in step with `splice.rs` (where strips land). (3) Anything visible at first paint that the script rewrites must not change width: relative `<time class="cd-rel">` tags are rendered by the server with the same age the script computes (`ui::rel_age` ≡ `fmtRel` in app.js — keep them equal; `title` = the absolute fallback), the older-Version banner uses a relative time, absolute times live only inside card bodies / the select options. (4) `performance.mark('cd:ready')` is set with `.cd-ready` (`markReady()`) — the perf runner's "interactive"; highlight elements are indexed by Thread id (`indexMark` / `marksOf` / `renameMarks` — anything that creates a mark or renames a `data-t` must keep the index), top-level blocks by binary search (`tops`, `outerBlocks`, `blockBefore`), `localizeTimes` uses cached `Intl.DateTimeFormat`s, and nothing re-lays out on `window.load` (only media without `width`/`height`). <!-- ---- end ticket 15 ---- -->
- **Layouts are CSS, not two DOMs:** `.cd-app` is a size container; at `@container cd (min-width: 850px)` the `.cd-layout` grid reserves a 320px margin column and every `.cd-strip` turns `position:absolute; left:calc(100% + 28px)` — its static position is already "right under its block", the script then sets `top` to the highlight's line and pushes cards apart (`layout()` in `app.js`; `.cd-app:not(.cd-ready) .cd-strip{visibility:hidden}` until it has run — no layout shift). Below 850px the same strips stay in the flow (layout C: `.cd-row` = status dot · frozen quote · author · snippet · replies; `.cd-body` shown by `.cd-open`). The narrow header is `#cd-line` (`name · vN · n open · n @you` + arrows) with `#cd-rest` as the tap-to-open overlay (`.cd-overlay-open`); wide, `#cd-rest` is `display:contents` inside the header. The threshold is one number (`WIDE = 850` in `app.js`, `850px` in the CSS) — keep them equal.
- **Highlights** are made by the script from `#cd-data` (`highlight()`): for a span it finds the outermost `[data-l]` blocks covering the range, searches the quote (`now` when refined, else the frozen quote) whitespace-insensitively in their text nodes and wraps the hit in `mark.cd-hl.cd-st-{status}[data-t]` (a quote the rendered text does not contain — Markdown syntax inside it — marks the block with `.cd-hl-block`); when the quote occurs more than once there (two items of one list, twice on a line — CMD-7, `S10-11`), `pickHit` gives each hit a source line (its innermost `[data-l]` block's first line + the soft breaks `\n` in that block's own text before it; a `pre`'s text starts after its opening fence) and takes the hits on the Thread's `line` in order, indexed by the item's `occ` (`view.rs` `occ_before`: how many times the text starts earlier on that source line of the viewed Version — the page and the card fragment read that Version's Markdown blob once for it, only when a placed span Thread exists); no hit on the line ⇒ the nearest, no usable line ⇒ the first hit (the old behavior). Chose `occ` from the server; rejected sending the column and guessing in the script because the rendered column drifts from the source column by every bit of Markdown syntax before it, and rejected fetching the source in the script because highlights must not wait for a request (the head source is lazy, and an older Version's is not on the page at all); an Asset Thread outlines `img|video|audio|object[src^="/a/{hash}"]` (`.cd-asset-hl`) or the `.asset-missing[data-ref]` placeholder. Refined = `.cd-st-refined` (dotted underline) + the card's `.cd-now`; resolved Threads and their marks carry `.cd-res` and stay behind `#cd-resolved` (`.cd-show-resolved` on `.cd-app`); with the toggle off a click on a `.cd-res` mark selects nothing, or the nearest open mark around it (CMD-20, `S28-01`) — only the History list and a `#tN` link may reveal a resolved Thread by turning the toggle on; orphaned Threads get no mark. `window.cd = {select, layout, loadNews}` is the hook ticket 11 builds on (selection pill, composer, optimistic mutations, keyboard, SSE).
- **Members** render through `ui::MemberBrief` (`display_name` + `.cd-auth` glyph: `has_password` ⇒ "signs in with the local password", else "authenticates with a Token"; `secondary` = harness/model text when the model ever carries it — never a "bot" badge). Comment bodies: `ui::comment_html` = `annotary_renderer::render(body, Options{assets:&[], embeds:false})` with `data-l` stripped and Asset links `target=_blank` (`ui::asset_links_blank` also runs over the Document HTML). Timestamps: `ui::time_tag(iso, rel)` → `<time datetime>` the script localizes (`cd-rel` = relative age); `<option data-at data-pre data-post>` for the Version select. The select (`.cd-vsw select` in `app.css`) keeps `padding-right:22px` and `text-overflow:ellipsis` so a long label stops before the native chevron instead of running under it (issue #5, `S35-01`). `tests/web/select-ink.ts` measures the clearance from the select's pixels (the blank columns between label and chevron), because a browser can report `padding` on a native control without honoring it; the ellipsis is still checked through the computed `text-overflow`. The browser test and the verify-live scenario both use it.
- **List page** (`listing.rs`): `docs::list_rows(st, auth, &ListQuery)` — the one query the API and the page share (same sort/filters/limit); query params `name`, `vault`, `deleted=1`, `mentions_me=1`, `action=ID|none`, `since` (CLI syntax via `cli::docref::parse_since`), `limit` (+50 per "more"); the title under the Name is `ui::title_for` (front matter `title:` else first H1, cached per blob hash — `annotary_renderer::title` renders the whole Markdown once per blob).
- **Decisions to keep:** Threads are spliced server-side so the first paint is final (never slotted in after load); one Thread element for both layouts (CSS decides card vs row); the resolved toggle is client-only (no reload, no request); History reads the events API on demand and ticket 11 adds the SSE subscription (opened only after `cd-ready`, never before the first paint); the page never auto-renders — `ensure_html` only falls back when the stored HTML is missing/too old (ADR 0001); 404/403 on page routes are HTML.

- **Brand (M3b):** `ui::shell_ex` puts `brand::HEAD_LINKS` (the two icons, the touch icon, the manifest) in every page's head, the login and error pages included. `brand::header_icon()` is first in `.cd-line` in both headers (`ui::top_nav`, `view.rs`): `a.cd-brand[href="/"]` around the small master inlined at 18 × 18 (`brand/icon.svg` with `class="cd-icon"`, width, height and `aria-hidden` added), inline rather than an `<img>` so the first paint is final. On the list and Settings pages `<b class="cd-name">annotary</b>` follows it; on a Document page the Vault crumb does and there is no wordmark. It is an `<a>`, so `.cd-line`'s tap-to-open overlay ignores it, and `flex:none` keeps it whole on a narrow header. The mark and the renderer are `DESIGN.md` (Brand) and `docs/dev/commands.md` (`make brand`).
- **Settings on every page (CMD-23):** every page opens `.cd-app` with `prefs::WebPrefs::app_attrs(extra)` — the Document and Version views (`view.rs`), the list (`listing.rs`); the login and error pages (`web.rs::simple_page`, `ui::simple` / `error_page`) have no signed-in Member and use `WebPrefs::default()` (Follow system). `WebPrefs::load(st, auth, headers)` reads the Member's Web Device in the same response, so the first paint is final: `cd-theme-light|dark|system`, `cd-show-resolved`, the inline variables `--cd-hl-light(-sel)`, `--cd-hl-dark(-sel)`, `--cd-text-scale`, and `data-cd-times|clock|keys|send|tz`. `#cd-data` gains nothing. Every browser is the one Web Device, so two browsers render the same `.cd-app` tag.
- **Tokens and the dark theme:** `app.css` names every color (`DESIGN.md` lists them): light on `:root` (the pre-CMD-23 values), dark in one block on `.cd-app.cd-theme-dark` and the identical block on `.cd-app.cd-theme-system` under `@media (prefers-color-scheme: dark)` (`ui.rs::the_two_dark_blocks_of_app_css_are_identical` keeps them equal and checks that dark redefines every light token). `.cd-app` paints `var(--cd-bg)` (it is `min-height:100vh`), and `html:has(>body>.cd-app.cd-theme-dark)` (and the system twin) turns the canvas black too, so overscroll never flashes white; `color-scheme` follows, so native controls and scrollbars match. `admin.css` uses the same tokens; the pairing QR code alone keeps a white ground. A new color goes in as a token in both palettes, never a literal in a rule.
- **Highlights:** `.cd-app` maps `--cd-hl` / `--cd-hl-sel` to the light pair, the dark block to the dark pair (fallbacks: Yellow). `mark.cd-hl` draws its text in `--cd-hl-ink` (light: `currentColor`; dark: `#000`, bright dark highlights per `record.md`), links in it `--cd-hl-link`, inline code `--cd-hl-code-bg`; a hidden resolved highlight goes back to `color:inherit`. Refined keeps its own `--cd-refined` / `--cd-refined-sel` and the dotted underline in both. Asset outlines, `.cd-hl-block` and the narrow strips' left rule read the same variables.
- **Text size:** `.cd-doc{font-size:calc(15px * var(--cd-text-scale,1))}`; the reading width is `72ch`, and layout A's grid column `calc(72ch * var(--cd-text-scale,1))`, so the measure scales with the text. Cards (`.cd-strip`, 13px) and the header do not scale (the plan scales Document text only). The margin still aligns: `layout()` measures the highlight wherever it lands.
- **Times:** `WebPrefs::times()` → `prefs::Times`; `times.tag(iso, rel)` replaces `ui::time_tag` in `view.rs` (cards, Comments, resolve lines, Action chip, older-Version banner, the card fragment) and `listing.rs`. Relative (the default) is exactly `ui::time_tag`. With Times shown as Absolute **and** the `cd_tz` cookie known, every `<time>` is rendered by the server in that zone (`<time class="cd-abs cd-localized" title="2024-03-05 12:04:09 EST">Mar 5, 2024, 12:04 PM</time>`, the year only when not this year's — the shape of the script's `fmtAbs`), so the script never rewrites it. Clock 12/24 is the setting; Follow system is the `cd_hc` cookie (`12`/`24`, no cookie = 12-hour). Chose a second small cookie, saved beside `cd_tz` by the same few lines of `app.js`; rejected letting the script reformat server times (a width change after the first paint is a layout shift) and rejected packing both into `cd_tz` (its value is validated as an IANA name). The script saves `cd_tz` / `cd_hc` (`Path=/; SameSite=Lax; Max-Age=1y`, raw values) on any page when missing or changed; nothing on that page changes.
- **Show resolved:** the server's `cd-show-resolved` also renders the toggle `checked` and the orphaned count over every orphaned Thread (what `updateOrphanedCount` computes); the toggle stays client-side.
- **Live (S29-25):** the Document page subscribes with `&me=1` and listens for `setting.changed`; the list page opens `GET /api/v1/events?me=1&kinds=setting.changed` (idle, after the first paint). Either way `applySettings()` (debounced 50 ms) re-reads `GET /api/v1/me/settings?device=web` and the catalog (once, for the preset colors; `hlPair` derives a custom color's selected shade with the rule of `settings::highlight_colors` — keep them equal) and puts the same classes, variables and data attributes on `.cd-app`; a changed Show resolved or text size re-runs `layout()`, a changed Times / Clock re-localizes every `<time>`. `window.cd.applySettings` is there for the Settings screen.
- **Tests:** `tests/web_theme.rs` (S29-24: both palettes for Follow system, Light / Dark, highlight and text-size variables, Show resolved, absolute times with `cd_tz` / `cd_hc`, the fragment, two sessions alike, login and error pages) and `tests/web/theme.spec.ts` (colors drawn in both `colorScheme`s, a change in one context applied in another without a reload, CLS 0 with large text + absolute times + Show resolved, the Send key). Each spec spawns its own server: a settings change is the Member's, and the shared server's owner is every other spec's browser.

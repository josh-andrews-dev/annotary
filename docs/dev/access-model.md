# Access model (ticket 06 — extend, don't rewrite)

Implementation notes, moved from the root `CLAUDE.md` on 2026-10-18 (read on demand; the
index is [README.md](README.md)). Extend them with the code they describe.

- **Rights & Grants:** `read / comment / action / write` per Vault, `read` implied by any other (`Grant::gives`). A Membership holds a list of Grants `{vault | "*", rights[]}`; **the Grant that applies to a Vault is the Vault's own entry, else `*`** (`Grant::applicable` / `Grant::allow`, used by `AuthMember::has_right`) — so `*` covers Vaults created later and `member grant codex notes comment` restricts codex to `comment` on `notes` while `*` keeps covering everything else. `Store::grant(by, member, vault, &[Right])` upserts one entry (empty rights removes it; `VaultNotFound` for an unknown Vault), `Store::replace_grants` replaces the list (`normalise_grants`: `*`/existing Vaults only, one entry per Vault, canonical right order, `InvalidGrant` on empty rights); both refuse a disabled Member (`MemberDisabled`) and append `member.granted {member, handle, grants}`. `set_grants` (02) still writes raw lists for tests. Blob transport / `/a/{hash}` need a Right on *some* Vault (`blobs::require_any_right`).
- **Owner-only, never grantable** (`auth.require_owner("what")` → 403 `what is owner-only`): `member add|rename|disable|grant|role`, `POST vaults`, Vault default Actions, purge, `settings` + the local password, another Member's tokens, editing/deleting any Comment. `Store::set_role` refuses demoting the last active owner and `disable_member` refuses disabling them (`StoreError::LastOwner` → 409 `last_owner` → exit 5); both are idempotent (`(view, changed)` / `bool`); `rename_member` changes `display_name` only (`member.renamed`, `member.role_set`, `member.disabled {member, handle}` events). Handles are never reused (checked incl. disabled).
- **Tokens:** `Store::mint_token_expiring(by, member, name, expires_at)` (future stored timestamp; disabled Member refused), `list_tokens(Option<member_id>)` / `token_row(id)` → `TokenRow {info, handle, display_name, member_disabled}` with `.status(now)` = `active|revoked|expired`; `revoke_token -> bool` (idempotent; `TokenNotFound`). `authenticate` rejects revoked/expired/disabled and stamps `last_used_at`. `token.minted {token, member, name, expires_at}` / `token.revoked {token, member}`.
- **Password & login:** `Store::set_password(by, member, Option<&str>)` (argon2id PHC in `members.password_hash`; `password.set|removed {member, handle}` — never the hash), `password_set()` (any active Member has one), `check_password(pw) -> MemberView` (`PasswordNotSet` → 409 `no_password`, `WrongPassword` → 401 `wrong_password`), `login(pw) -> (MemberView, NewToken)` (a Token named `login`), `founding_owner()` (earliest active owner — whom loopback trust signs in). `GET /api/v1/health` carries `password_set` (unauthenticated; `login` reads it before prompting).
- **Sessions:** `Store::open_session(member, via) -> NewSession {id (sha256), plain (`cds_…` cookie value), expires_at}` (365 d, `session.opened {member, handle, via: login|loopback}`), `authenticate_session(plain) -> Option<AuthMember>` (stamps `last_seen_at`), `reauthenticate(&AuthVia) -> Option<AuthMember>` (CMD-8: the same checks for a Token or session already resolved, by its id, read-only — what the SSE stream calls on every wake), `end_session(id) -> bool` (`session.ended`). `AuthMember.via` is `AuthVia::Token {id} | AuthVia::Session {id}` (there is no `token_id` field any more).
- **Auth in the server** (`server/auth.rs`): `Auth` reads a pre-resolved value from the request extensions first, else `Authorization: Bearer` (→ `authenticate`), else the `cd_session` cookie (→ `authenticate_session`), else 401 `missing_credential`; a bad bearer ⇒ 401 `unauthorized`, a dead cookie ⇒ 401 `session expired or ended`. **API routes never sign anyone in.** Web pages go in the `web_pages` router in `app.rs` (behind `web::require_web_auth`): bearer/cookie sign in; with neither, a **loopback** request while **no password is set** is signed in as the founding owner and the response gets `Set-Cookie: cd_session=…; Path=/; HttpOnly; SameSite=Lax; Max-Age=1y`; otherwise a request accepting `text/html` is redirected to `/login?next=<path>` and anything else gets 401 JSON. `GET /login` (form; auto-signs a loopback browser in when no password — a non-loopback one gets `web::no_password_page` instead (CMD-14): set a password from the server's loopback URL (`st.url`), or `annotary pair`; already signed in ⇒ redirect `next`), `POST /login` (`password`, `next` — same-origin paths only) ⇒ cookie + 303, wrong ⇒ 401 + the form; `POST /logout` ends the session, clears the cookie, 303 `/login` (or `/`). `web::page`/`esc` build the minimal HTML; ticket 10 replaces `web::index` and adds `/d/{id}` in the same router; ticket 12 restyles `/login`. `server::run` uses `into_make_service_with_connect_info::<SocketAddr>()` (the middleware reads `ConnectInfo`; without it nothing is ever auto-signed-in).
- **API** (`server/access.rs` has the table): `GET /api/v1/members/{handle}` (+ `tokens[]` for owner/self), `POST …/rename {name}` · `…/disable` · `…/role {role}` · `…/grants {vault, rights[]}` (upsert; `[]` removes), `PUT …/grants {grants[]}`; `GET /api/v1/tokens?member=HANDLE|*` (own; owner any/all), `POST /api/v1/tokens {member?, name?, expires_at?}` → 201 with `token` once, `DELETE /api/v1/tokens/{id}` (own or owner; `revoked` false when it already was); `POST /api/v1/login {password}` (unauthenticated) → member + `token`; `POST /api/v1/logout` (bearer ⇒ revoke that Token; cookie ⇒ end that session); `GET /api/v1/settings` · `PUT /api/v1/settings/password {password|null}` (owner; the caller's own password); `POST /api/v1/vaults {name}` (owner, 409 on a duplicate). `token_json` never carries the plain text or hash. <!-- ---- ticket 12 ---- --> `POST /api/v1/vaults/{name}/rename {name}` · `DELETE /api/v1/vaults/{name}` (owner; see "Web UI: owner screens"). <!-- ---- end ticket 12 ---- --> <!-- ---- CMD-5 ---- --> `GET /api/v1/vaults` rows carry `documents` / `deleted` (`vault_json_counted`). The profile-Vault headers (`server/vaults.rs` module docs): `ProfileVaultHeader` (extractor; `none()` for the web list) + `echo_layer` (whole router: a request with the header gets an `EchoSlot`, the response — success or error — gets `x-annotary-resolved-vault[-id]` / `x-annotary-deleted-vault`); `scoped_vault(st, auth, pv, explicit, right) -> Scope::{Vault, Every, Deleted}` (`scoped_vault_ids` for reads) is what `docs::list_rows` / `resolve` / `create` and `threads::mentions` call; `echo_profile_vault` for `GET /vaults` and `/me`. Rights: a resolved Vault is echoed only when the caller holds the route's right on it, else `missing_right` names the profile's name; `vault_not_found` adds `Vault OLD was renamed to NEW` only when the caller may read NEW. `Store::resolve_profile_vault` / `renamed_from_hint` (`store/src/vaults.rs`) do the lookup (events with `doc_id IS NULL`). <!-- ---- end CMD-5 ---- --> Status→exit: 409 `last_owner` / `disabled` / `no_password` → 5, 401 `wrong_password` → 3, 400 `invalid_grant` → 1.
- **CLI:** `member rename|disable|grant|role` print the Member's updated `member list` row (`@h name role grants`, `role (disabled)`), `--json` = the `member list` record; `member grant HANDLE VAULT|* RIGHTS` (`cli::member::parse_rights`: comma list, `none` removes; `@` on handles is optional, `clean_handle`). `token mint [--name] [--expires DUR|DATE] [--member H]` prints like `member add` (`ANNOTARY_TOKEN=…` once; TTY paste hint), `token list [--member H|*] [--all]` = `MEMBER NAME CREATED LAST USED EXPIRES ID` (revoked only with `--all`, `revoked`/`expired` in EXPIRES; else the local date or `-`), `token revoke ID` = `ID @member revoked` (`cli::token::parse_expiry` for durations/dates). `login [--server URL]`: prompts on **stderr** (`cli::prompt::Prompter` with `Sink::Stderr`; non-TTY reads stdin lines, `ANNOTARY_PASSWORD` answers the password), checks `health.password_set` first (exit 5 with a hint), then `POST login`, saves profile `-p NAME` (default: the handle; an existing profile keeps its `vault`), prints `Signed in as @h (role). Saved profile "NAME" → PATH`, then notes `use it with -p NAME` on stderr; there is no default profile); `logout` (profile from `-p` or `ANNOTARY_PROFILE`) revokes via `POST logout` (best effort — unreachable/rejected still forgets locally with a note) and removes only the token. `profile list` (`NAME SERVER MEMBER`, MEMBER from each server's `/me`, `-` on failure; CMD-5: the same call heals the profile's `vault` / `vault_id`), `profile add NAME [--server] [--token] [--vault]` (refuses to overwrite, exit 5), `profile remove NAME`. No default profile (removed 2026-10-21: an agent fell back to the owner's default and commented as them); credential order `-p` > `ANNOTARY_TOKEN` > `ANNOTARY_PROFILE`, so an agent's `-p` beats whatever the human exported (`client::resolve_credential`). `Config::save` is atomic (temp + rename, 0600); `Api::anonymous(server)` for `health`/`login`.
- <!-- ---- CMD-4 ---- --> **Login throttle and cross-site refusal** (`server/login_guard.rs`, module docs have the rules): `AppState.login_throttle` (in memory, a restart clears it) counts wrong passwords from `POST /login` and `POST /api/v1/login` together, per client (peer IP; IPv6 by /64) and, for non-loopback peers, for the account; 5 per client or 20 account-wide within 15 min ⇒ 429 (`too_many_attempts` + `Retry-After` from the API → exit 5; the form with "Too many wrong passwords" from the page) until the oldest is 15 min old, without checking the password; loopback is never locked by the account limit; a success clears the client. `refuse_cross_site` is a layer on the whole router: a non-GET/HEAD/OPTIONS request without a bearer Token that `Auth` would use (an empty `Bearer` does not count; `POST /login` is never exempt) whose `Sec-Fetch-Site` is not `same-origin`/`none`, or (without that header) whose `Origin` is not the `Host`, gets 403 `cross_site`; no header ⇒ allowed (CLI, curl). Each refusal and each lock is a `WARN` line in the server log. <!-- ---- end CMD-4 ---- -->
- <!-- ---- CMD-17 ---- --> **Behind a local reverse proxy** (Tailscale Serve, say): `login_guard::client_ip(peer, headers)` is the client every trust and throttle decision reads (`web::is_loopback`, `GET`/`POST /login`, `POST /api/v1/login`): a loopback peer with any of `FORWARDED_HEADERS` (`X-Forwarded-For`, `Forwarded`, `X-Real-IP`, `Tailscale-User-Login`) is the last `X-Forwarded-For` entry when that is a non-loopback IP, else `0.0.0.0`, so never loopback; any other peer is itself. A new trust decision uses `client_ip`, never `ConnectInfo` alone. <!-- ---- end CMD-17 ---- -->

# Web UI: owner screens & login (ticket 12 — extend, don't rewrite)

Implementation notes, moved from the root `CLAUDE.md` on 2026-10-18 (read on demand; the
index is [README.md](README.md)). Extend them with the code they describe.

- **Files:** `server/admin.rs` (`members_page` / `settings_page` = `owner_page(...)` → `ui::page_ex(title, body, ADMIN_CSS, ADMIN_JS)`; `member_card(m, tokens, vaults, me)` and `vault_card(v, count)` are the two card renderers, shared by the pages and the fragments `member_fragment` / `vault_fragment`), `server/ui/admin.css` + `admin.js` (inlined after `app.css` / `app.js` only on `/members`, `/settings`, and — CSS only — `/login`; the Document pages carry nothing of it), `ui::top_nav(st, auth, current)` (the shared top bar: `annotary` + `<nav id="cd-nav">` with Documents and, for owners only, Members / Settings; the signed-in Member; Sign out when a password is set — `listing.rs` uses it too; its narrow-container rules sit in `app.css` since the list page has no `admin.css`), `ui::shell_ex` / `page_ex`, `web.rs` (`/login` = `simple_page` on the shell: `.cd-app.cd-loginpage > main.cd-simple.cd-login`, `#cd-loginform`, `.cd-err[role=alert]`; with no password, a non-loopback browser gets `ol#cd-loginsteps.cd-loginsteps` (CMD-14)), `server/vaults.rs` (rename / delete), `crates/store/src/vaults.rs`, `window.cd.localize` in `app.js` (the owner script localizes the `<time>` tags of freshly drawn cards).
- **Members screen:** one `article.cd-mem[data-handle]` per Member (`list_members` order): `MemberBrief` (name + auth glyph) · `@handle` · role chip · `disabled` chip; the auth hint in words (`signs in with the local password` / `authenticates with a Token` — never a "bot" badge); the Grants summary (`every Vault: read, comment, action, write` · `notes: write` · `no access`); the live Tokens table (name · created · **last used** (`cd-rel`) or `never` · expires · id · Revoke; revoked ones hidden behind a `· N revoked` note; `Mint Token` inline form: name, expiry `YYYY-MM-DD` or ISO); `details.cd-advanced` = role `<select>` + Save, the Grants grid (`*` row + one row per Vault × read/comment/action/write checkboxes, `PUT …/grants` with the checked rows — no box on a row = no Grant). A disabled Member keeps Rename and its Tokens (revocable) but has no Disable / Mint / Advanced (the server would refuse them anyway); it has **Enable** instead (`[data-act=enable]`, an inline confirm → `POST …/enable` → the card re-drawn active, its old Tokens now revoked, the active count up one). "Add member" = `#cd-addform` (handle + optional name) → `POST /api/v1/members` → the token-once panel `.cd-tokonce` (`ANNOTARY_TOKEN=…` line, Copy via the clipboard API with a select-all fallback, Dismiss) under the form + the new card fetched as a fragment; minting puts the same panel inside the Member's card. Every mutation re-draws the card from `GET /members/{handle}` (an open Advanced stays open); errors land in the nearest `.cd-err`.
- **Settings screen:** `#cd-set-password` (state text; new + again → `PUT /api/v1/settings/password {password}`; Remove → `{password: null}`; the page updates its state client-side — the current session stays signed in, the top bar shows Sign out on the next page), `#cd-vaults` (`article.cd-vault[data-vault]` per Vault: name, `N Documents (M deleted)` / `empty`, created, Rename / Delete inline, the default Actions editor `table.cd-actsed` with `{id, label, intent}` rows + ↑ ↓ × / Add Action / Save Actions → `PUT /api/v1/vaults/{name}/actions {available}` then the card re-drawn from `GET /settings/vaults/{name}`; create form `#cd-vaultnew` → `POST /api/v1/vaults`), `#cd-set-purge` (checkbox + days → `PUT /api/v1/settings/auto-purge {days|null}`; `run it now` → `POST /api/v1/housekeeping` → a one-line report).
- **Vault rename / delete** (`Store::rename_vault` / `delete_vault`): Grants are stored by Vault *name*, so a rename rewrites every Membership's Grants naming it in the same tx (`vault.renamed {vault, name, from, grants_followed[]}`); delete needs an empty Vault (no Documents at all — deleted ones must be purged first: 409 `vault_not_empty`) that is not the last one (409 `last_vault`) and drops the Grants naming it (`vault.deleted {vault, name, grants_dropped[]}`). `validate_vault_name` (not empty, no `/`, no control chars, never `*`) is shared with `create_vault`, which now returns `VaultNameTaken` (409 `conflict`, as before). Profiles / Sidecars on disk keep an old name (push binds by id) until CMD-5: a profile follows on its next call (`docs/dev/cli-conventions.md`), a Sidecar on its next push or pull.
- **Decisions to keep:** the owner screens are ordinary server-composed pages behind `require_web_auth` + `require_owner` — no separate admin auth, no API route added for them (everything the screens do goes through `/api/v1` with the cookie, so the CLI could do the same); card markup has exactly one renderer (Rust), the script builds only inline editors / confirms / the token-once panel / a new Actions row; a plain Token appears exactly once (the panel) and never in a page render; a Member never sees the Members / Settings links and gets the HTML 403 page; the login page stays unauthenticated and its contract (`name="password"`, `next`, `Wrong password.`, 401) is unchanged; `admin.css` / `admin.js` are never inlined into the Document pages (perf budgets of 15).

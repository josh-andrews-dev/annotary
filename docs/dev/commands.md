# Commands

Implementation notes, moved from the root `CLAUDE.md` on 2026-10-18 (read on demand; the
index is [README.md](README.md)). Extend them with the code they describe.

- `cargo test` — crate unit tests + in-process server integration tests (`crates/annotary/tests/*.rs`, `crates/*/src` `mod tests`); must stay < 60 s. Failpoints (`fail` crate) are on only under `cargo test`.
- `make e2e` — trycmd goldens against a real spawned `annotary serve` (`crates/annotary/tests/e2e.rs`, `#[ignore]`d in plain `cargo test`); Playwright joins here from ticket 10.
- `make check` — `fmt-check` + `clippy -D warnings` + `test` + `e2e` + `spec-check` + `wasm-check` + `perf` (ticket 16: perf joined; `PERF=0 make check` or `make check-ci` is the same without it, for a machine without the release toolchain / Chromium). It is the definition of done (`docs/PHASE1-DONE.md`). Keep it green.
- `make trim` (`scripts/trim-target.sh`) — removes `target/` when the toolchain changed, nothing was built for 14 days, or it passed 15 GB (`TRIM_IDLE_DAYS` / `TRIM_MAX_GB`; `--dry-run`). Every cargo-using `make` target runs it first, and `.claude/settings.json` runs it at session start/end; it skips while a build or a `target/` binary is running. `TRIM_TARGET_DIR` names another folder to trim (never `CARGO_TARGET_DIR`, which a developer may share between projects; `/`, `$HOME` and the repo are refused): a workflow on a self-hosted runner can set both to one folder per runner (`TRIM_MAX_GB=10`, dev builds with `line-tables-only` debuginfo) in place of a GitHub cache, and the Playwright harness and `make perf` find the binaries under `CARGO_TARGET_DIR`.
- `make goldens` — `TRYCMD=overwrite make e2e` to regenerate goldens (review the diff!). `make fmt`, `make clippy`, `make spec-check` exist too. All targets work from a fresh shell with only `~/.cargo/bin` on PATH. <!-- ---- ticket 13 ---- --> `make launchd-test` = the live `launchctl` round trip (`ANNOTARY_LAUNCHD_TESTS=1`, macOS only, not part of `make check`; temp HOME + data dir + private label, so the real `com.annotary.server` is never touched). <!-- ---- end ticket 13 ---- -->
- `make brand` — re-render `brand/` from its masters `brand/mark.svg` and `brand/mark-small.svg` with `scripts/brand/render.py` (`uv run --no-project`, the root `.python-version` pins Python to 3.13, the minor version because an older uv on a runner cannot download a newer patch and pixels do not depend on it; no dependencies) after changing a master, and commit the result. `cargo test -p annotary --test brand` runs `scripts/brand/test_render.py`, which fails when a committed file differs from a fresh render (SVG bytes, PNG and `.ico` pixels); the test runs under plain `python3` (standard library only), so a contributor's `make test` needs no `uv`.
- <!-- ---- ticket 10 ---- --> `make web` — the Playwright suite alone (`tests/web/`; `node_modules/.stamp` runs `npm ci` once from the committed lockfile — `@playwright/test` is pinned, and `npx playwright install chromium` fetches its Chromium once; `make e2e` depends on it). `npx playwright test -g "narrow"` / `--headed` / `--trace on` for one test; traces and screenshots land in `target/playwright/`; `CD_WEB_KEEP=1` keeps the seeded temp stores after a run. <!-- ---- end ticket 10 ---- -->
- `make size-check` — the size report (`crates/annotary/tests/size_report.rs`, `#[ignore]`d in plain `cargo test`): seeds the full perf fixture and fails when `perf/size-report.json` differs from the measurement or a number is above its ceiling in `perf/BUDGETS.md`; part of `check-ci` and of the `cargo test` jobs in CI. `make size-report` rewrites the file (`SIZE_REPORT=overwrite`). `make workflow-test` (part of `make test`) runs the pull request checks' scripts' tests, `node --test .github/scripts/*.test.cjs`.
- <!-- ---- ticket 14 ---- --> `make token-report` — regenerate `tests/token-report.md` (`TOKEN_REPORT=overwrite cargo test -p annotary --test token_report`) after a deliberate change to what `status` / `wait` / `mentions` / `show` / `thread show` / `--help` / SKILL.md print; the plain test asserts ±20% of the prototype's numbers *and* that the committed report is current. `E2E_GROUPS=95-agent-flow,96-human-tty cargo test -p annotary --test e2e -- --ignored` runs only those trycmd groups while iterating (earlier seeds absent). <!-- ---- end ticket 14 ---- -->
- <!-- ---- ticket 15 ---- --> `make perf` — the perf suite: `cargo build --release -p annotary -p annotary-perfgen`, then `npx playwright test -c perf/playwright.config.ts` (one worker; `perf/global-setup.ts` spawns the **release** server and runs `perfgen seed` — the ≥ 5,000-line / ≥ 500-Thread fixture pushed through the real binary; `perf/perf.spec.ts` measures with CDP, cold cache per run, median of 5, prints the table, writes `target/perf/results.{md,json}`, asserts `perf/BUDGETS.md`). `PERF_RUNS=3` / `PERF_SCALE=smoke` / `PERF_SEED=N` tune a local run; `CD_PERF_KEEP=1` keeps the seeded store. Part of `make check` since ticket 16 (≈ 25 s on the dev Mac; `PERF=0` skips it); it needs a quiet machine (`perf/README.md`), so a shared CI runner's numbers mean nothing. `perfgen stats|write --out DIR` show the fixture without a server. <!-- ---- end ticket 15 ---- -->
- Toolchain: rustup stable via `~/.cargo/bin`; node at `~/.local/bin`.
- `make diff-worst-case`: the Compare page's worst inputs (`crates/diff/tests/worst_case.rs`, ignored by `cargo test`) against its limits, 2 s and 64 MiB per diff, one row per shape. Add a shape when a new worst case turns up.

# Server conventions

Implementation notes, moved from the root `CLAUDE.md` on 2026-10-18 (read on demand; the
index is [README.md](README.md)). Extend them with the code they describe.

- Routes under `/api/v1/…` in `server/app.rs`; handlers take `State(st): State<AppState>` and `auth: Auth` (bearer → `AuthMember` or 401); `auth.require_owner("what")` / `auth.require_right(vault, Right::X)` give 403 with the right named (rights come from Grants only — the owner's `*` grant covers every Vault; `vaults::readable_vaults` scopes queries). `/api/v1/health` is the only unauthenticated API route. Bodies: `Result<Json<T>, JsonRejection>` so bad JSON is a 400 `{error:"invalid"}`; raw bodies use `axum::body::Bytes` (see `blobs.rs`). Status→exit: 401→3, 403→4, 404→2 (also `ambiguous`), 409→5 (`conflict`, `head_moved`, `blob_missing`, `deleted`, `not_deleted`), 413→5 (`too_large`), 400→1 (`invalid`, `invalid_name`, `invalid_manifest`); map new `StoreError`s in `server/error.rs`. <!-- ---- ticket 05 ---- --> 409 `not_head` / `undeclared_action` → 5, 400 `invalid_actions` → 1; `Right::Action` is checked by `auth.require_right(vault, Right::Action)` on `POST …/actions` only. <!-- ---- end ticket 05 ---- --> <!-- ---- ticket 07 ---- --> 400 `invalid_placements` → 1, 409 `asset_not_on_head` / `asset_missing` → 5. <!-- ---- end ticket 07 ---- --> <!-- ---- ticket 17 ---- --> 409 `head_moved` carries `base` / `head` / `by` (`ApiError.extra`) and a hint per `HeadMovedReason`. <!-- ---- end ticket 17 ---- --> <!-- ---- ticket 06 ---- --> 409 `last_owner` / `disabled` / `no_password` → 5, 401 `wrong_password` → 3, 400 `invalid_grant` → 1; `Auth` also accepts the `cd_session` cookie; `POST /api/v1/login` and `/login` are unauthenticated too; web pages live in the `web_pages` router (loopback trust / login redirect) — see "Access model". <!-- ---- end ticket 06 ---- -->
- <!-- ---- ticket 11 ---- --> `GET /d/{id}/t/{tid}?v=N` (`view::fragment`, in the `web_pages` router) is the one page route that answers JSON: `{html, item, hidden, head, version}` — the Thread's card exactly as `thread_card` renders it for the caller (a `Viewer`), so the page and the live feed share one renderer; 404 as JSON. Mutations from the browser go through `/api/v1` like the CLI's (`POST …/threads`, `…/replies`, `…/resolve|reopen`, `PUT|DELETE …/threads/{cid}`, `POST …/actions`) with the `cd_session` cookie — nothing page-specific was added to the API. <!-- ---- end ticket 11 ---- -->
- M3b: `server/brand.rs` serves `/favicon.ico`, `/icon.svg`, `/apple-touch-icon.png`, `/manifest.webmanifest` and the manifest's `/icon-192.png`, `/icon-512.png`, `/icon-mask.png` before sign-in, merged beside `web_pages` so `require_web_auth` never sees them, and they read no store. The bytes are `brand/`'s, built into the binary (`include_bytes!`); `public, max-age=86400` (the names are unversioned), `nosniff`, and `icon.svg` carries the same CSP as a served SVG Asset. Each has a `Need::Public` row in `tests/access_api.rs`.
- <!-- ---- ticket 18 ---- --> `POST /api/v1/pairing` (any Member for themselves, owner for another; 409 `no_public_url` → 5); `health` and `settings` carry `public_url` / `link_base`. <!-- ---- end ticket 18 ---- -->
- <!-- ---- ticket 12 ---- --> `GET /members` / `GET /settings` (owner screens) and their fragments `GET /members/{handle}` / `GET /settings/vaults/{name}` (JSON `{html, …}` — the one renderer of a Member / Vault card, like 11's Thread fragment) live in the `web_pages` router; the pages answer a Member with the 403 HTML page (`ui::error_page`), the fragments with 403 JSON. 409 `conflict` (Vault name taken) / `vault_not_empty` / `last_vault` → 5. <!-- ---- end ticket 12 ---- -->
- <!-- ---- ticket 08 ---- --> `GET /api/v1/events` is the one long-lived route (long-poll ≤ 30 s, or an SSE stream): it awaits `AppState.events.changed()` *and* `AppState.shutdown.changed()` and never holds the store across the await; anything that needs "tell me when something happens" — the web live feed, History — reads it rather than polling other routes (see "Events, `wait`, live feed"). `server::run` ends shutdown within `DRAIN_MAX` (3 s) of the signal whatever is attached — a new long-lived route must watch `st.shutdown` too. <!-- ---- end ticket 08 ---- -->
- <!-- ---- ticket 13 ---- --> `server::run` spawns the housekeeping ticker next to the listener (`server/housekeeping.rs`; interval 1 h, `ANNOTARY_HOUSEKEEPING_INTERVAL` seconds for tests; aborted on shutdown) — a tick runs on `spawn_blocking` and never holds the store across an await; `POST /api/v1/housekeeping` (owner) runs one now; `PUT /api/v1/settings/auto-purge {days}` (owner) and `GET /api/v1/settings.auto_purge_days` are the setting's API (see "Daemon, export, housekeeping"). <!-- ---- end ticket 13 ---- -->
- `serve` is foreground, logs to stderr (`tracing`, `RUST_LOG`), loopback unless `--allow-remote` (`--bind`; ticket 18), `--port 0` = ephemeral, `--setup-only` = first-run then exit. First-run setup is scriptable: prompts read stdin lines when not a TTY (EOF/blank = default; an idle pipe counts as EOF after 2 s, so `annotary serve &` never hangs) and honor `ANNOTARY_SETUP_HANDLE` / `_NAME` / `_PASSWORD`; it prints the owner Token once as `ANNOTARY_TOKEN=…` (the owner's way to a CLI credential until `login`, ticket 06). <!-- ---- ticket 06 ---- --> `login` exists now (needs a local password; `ANNOTARY_PASSWORD` scripts it) — the setup line stays for passwordless owners; the prompts of both live in `cli/prompt.rs`. <!-- ---- end ticket 06 ---- --> CMD-23: the hidden `serve --print-schema-version` prints `SCHEMA_VERSION` and exits before the data dir is touched (no LOCK, no migration); `deploy/linux_install.sh` compares it with `store/meta.json` to decide whether to write `snapshots/pre-schema-N.tar` before the new binary migrates the store.

<!-- ---- ticket 07 ---- -->
- <!-- ---- CMD-23 ---- --> `GET /settings` and `GET /settings/{group}` (the Settings screen, every Member; `settings_page.rs`) and `GET /settings/server/{members,vaults,general}` (the owner pages, 403 page for a Member; `admin.rs`) replace the ticket-12 pages above; `GET /members` 308s to `/settings/server/members`; the fragments are unchanged. An unknown group or Server page is the 404 page (`ui::error_page`). See [web-settings.md](web-settings.md). <!-- ---- end CMD-23 ---- -->

<!-- ---- M3 (Hermes plan) ---- -->
- **Embedded requests** (`X-Annotary-Embed: 1`, `server/embed.rs`): the outermost layer, `embed::parts`, cuts an embedded GET answer over `PART_MAX` into `206` parts (`X-Annotary-Part` / `-Parts` / `-Etag` / `-Status`; `412` for a stale etag); embed pages and `GET /embed/shell` carry `Content-Security-Policy: sandbox allow-scripts`. An embedded request is an ordinary Bearer request in every other way (`refuse_cross_site` exempts Bearer).
<!-- ---- end M3 (Hermes plan) ---- -->
- Compare Versions: `GET /d/{id}/diff?from=A&to=B` (`compare.rs`, the `web_pages` router, `read`) is a page like `/d/{id}`: errors are the HTML pages, its row in `tests/access_api.rs` is `GET /d/{id}/diff (page)`.

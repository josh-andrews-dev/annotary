# CLI conventions

Implementation notes, moved from the root `CLAUDE.md` on 2026-10-18 (read on demand; the
index is [README.md](README.md)). Extend them with the code they describe.

- Exit codes (only defined in `crates/annotary/src/exit.rs`, `Exit`): `0 ok · 1 usage/other · 2 not found/ambiguous · 3 no credential (incl. 401) · 4 missing right (403) · 5 conflict/refused (409, LOCK, guards, --strict) · 6 server unreachable · 7 wait timeout`. clap usage errors are mapped to 1.
- Errors: build a `CliError` (`CliError::refused(msg).hint(h).detail(line)`); `run` prints one line `error: MSG — HINT` (+ detail lines) on **stderr**, or `{"error","message","hint"}` on stderr under `--json`. <!-- ---- ticket 08 ---- --> A `bare` error prints its message verbatim in text mode and `extra` fields join the JSON object — only `wait`'s timeout uses them (`CliError::wait_timeout`). <!-- ---- end ticket 08 ---- --> Server errors are `{error, message, hint}` JSON with the status the CLI maps (`client::map_status`); build them with `server::error::ApiError`.
- Output (`output.rs`): results on stdout; notes/progress/hints on stderr via `out.note()` (silenced by `-q`). Non-TTY = tab-separated, one record per line, no header, no color; TTY = same fields/order, aligned, dim header (`out.table(header, rows, align)`); single-line results (`push`, `pull`, `show`, `status`, `delete`) join their fields with `\t` (non-TTY) or two spaces (TTY), and `show`/`push` append `[server]/d/[id]` on a TTY. `ANNOTARY_TTY=1|0` forces the mode (tests); `--no-color` / `NO_COLOR` disable color. Handles print as `@handle` in text, `handle` in JSON. Timestamps: stored with millis, shown as `…:02Z` in JSON (`iso_seconds`) and relative (`relative_age`: `4d`, `2m`) in text — both TTY and non-TTY, as the CLI prototype goldens show.
- DOC arguments: `cli/docref.rs::resolve(ctx, api, doc, vault, DeletedMode)` — path (`.md` or contains `/`) ⇒ id from the sibling Sidecar; else the server's `resolve` endpoint (id first, then Name unique among the Vaults in scope: `vault` arg → profile `vault` → every readable Vault); ambiguous/unknown ⇒ exit 2. `DeletedMode::Exclude` for verbs on live Documents (`show`/`status`/`delete`), `Only` for `restore`/`purge`, `Any` for `pull`/`versions`/`--doc`. `select_vault` picks the Vault for a new Document; `parse_since` handles `--since` (`2h`, `3d`, dates, ISO).
- `--json [FIELDS]` (put it after the verb): declare a `FieldSpec { all, default }` per verb, build `serde_json::Map` records, call `out.json_records(&SPEC, records, single)`; bare = default set, `a,b` narrows (unknown field → exit 1 listing fields), `?` prints `all` and exits without calling the server; minified, empty/null/false omitted (`serde_json` has `preserve_order`, so insertion order is output order).
- Global flags: `-p/--profile` (`ANNOTARY_PROFILE`), `--json`, `-q`, `--no-color`, `--data-dir` (`ANNOTARY_HOME`), `-h`, `-V`. Credential order in `client::resolve_credential`: the `-p` flag → `ANNOTARY_TOKEN` env → `ANNOTARY_PROFILE` → exit 3 (no default profile since 2026-10-21; the flag is not clap-env-backed, `Ctx::profile_name` reads `ANNOTARY_PROFILE` for `login`/`logout`); server: `ANNOTARY_SERVER` → profile `server` → `http://127.0.0.1:7377`.
- <!-- ---- ticket 13 ---- --> `daemon` and `export` are data-dir verbs like `serve`: they never need a credential; `daemon` exits 1 off macOS, 5 for `start`/`restart` without a plist and for a store held by a foreground `serve` (LOCK), 1 when `launchctl` itself fails; `export` exits 5 for an existing file without `--force` / no store, 1 for a name that is not `.tar`. <!-- ---- end ticket 13 ---- --> <!-- ---- CMD-22 ---- --> `password --clear | --set [--member HANDLE]` (`cli/password.rs`) is a data-dir verb too: it opens `store/` itself (refused, exit 5, while a `serve` holds the `LOCK`; exit 5 with no store, which it never creates), `--clear` without `--member` removes every active Member's password (then loopback trusts the owner again), `--set` defaults to the owner and reads the password only from the prompt (`ANNOTARY_PASSWORD`, a stdin line, or no-echo TTY); `MEMBER PASSWORD` per Member changed, the note after the records; events by the founding owner. <!-- ---- end CMD-22 ---- -->
- Adding a verb: `cli/<verb>.rs` with clap `Args`/`Subcommand`, register in `cli/mod.rs` `Command`, dispatch in `run`; call the API via `ctx.api()?.get/post/delete/put_bytes/get_bytes` (`client::qs` percent-encodes query values); add a `--json ?` case (a line in `10-readonly/json-fields.trycmd`), a TTY + non-TTY parity case, and every exit-code path to `tests/e2e/`. <!-- ---- ticket 14 ---- --> Add it to the top-level help in `cli/help.rs::TOP` (the grouped reference the prototype wrote; `help::tests::every_flag_is_documented` fails when a verb the templates cover gains a flag its help does not mention, and the top-level help must name every subcommand), regenerate `10-readonly/help.trycmd`, and check `tests/token-report.md` (`make token-report`) — the top-level help stays within 20% of the prototype's count, which `tests/token_report.rs` enforces. A verb with a hand-written help is `#[command(help_template = help::X)]` on its `Command` variant; the template is literal text (no `{…}` nesting — clap reads `{tag}`; unknown tags print verbatim, an unclosed one is dropped), so global options are documented once in `TOP` only. If the agent should use the verb, add one line to `crates/annotary/skill/SKILL.md` (≤ 60 lines, within 20% of the prototype's count — `token_report.rs` guards both; bump nothing else: the source carries the `0.0.0` placeholder and `skill_md()` pins `metadata.version` to `crate::VERSION`, the build-time `ANNOTARY_VERSION` (CMD-2), asserted by `cli::skill::tests`). <!-- ---- end ticket 14 ---- -->
- <!-- ---- CMD-5 ---- --> `vault list` = `NAME DOCUMENTS DELETED CREATED` (DELETED = deleted Documents still in it; CREATED relative), `vault create NAME` / `vault rename OLD NEW` print that row (`rename --json` adds `from` and `profiles`, the local profiles it updated), `vault delete NAME` prints `NAME deleted` (`--json {name, id, deleted, profiles}`); create / rename / delete are owner-only (exit 4); unknown 2; taken / not empty / last Vault 5. **The profile's Vault follows a rename** (`cli/vault.rs`, `client.rs`): `Ctx::api()` builds `Api::new(&cred).with_profile_vault(&cred, config, quiet)`, which sends `X-Annotary-Profile-Vault` (`qs`-encoded name) + `X-Annotary-Profile-Vault-Id` on every request, and `Api::observe` reads `X-Annotary-Resolved-Vault` / `-Id` / `X-Annotary-Deleted-Vault` off every response and calls `client::heal_profile` (reload, change only if the profile's `vault` is still what was sent, atomic save; a note `note: Vault "a" is now "b" — updated profile "p"` / `… was deleted — cleared it from profile "p"` unless `-q`; a `vault_id` backfill is silent). The profile is `Credential.vault_profile` (`-p`, or `ANNOTARY_PROFILE` under `ANNOTARY_TOKEN`). Verbs still pass the profile `vault` as `vault=` (older servers); `push` of a new Document retries `select_vault` once without the profile Vault on 404 `vault_deleted`. `profile list`'s `/me` call carries the header too, so it reconciles every reachable profile. `vault rename` / `delete` update local profiles on the same server whose `vault_id` is that Vault (or, without an id, whose `vault` is the old name). <!-- ---- end CMD-5 ---- -->
- <!-- ---- CMD-23 ---- --> `settings [list] [--device NAME]` / `settings get KEY` = `KEY VALUE SOURCE KIND` per setting (`cli/settings.rs`; VALUE plain — `system`, `100`, Default Vault by the Vault's name or `any`; SOURCE `default|all|device|user`; TTY: aligned with a header for `list`, two-space fields for one record); `--json` fields `key value source kind label group device` (default the first four; `label`/`group` come from this binary's `annotary_store::settings::CATALOG`, `device` = the Device id a device setting was resolved for). Without `--device` a device setting shows its All devices value: the CLI sends no `X-Annotary-Device` and so never makes a Device (`GET /api/v1/me/settings` with no Device). `settings set KEY VALUE` / `settings reset KEY`: a user setting takes no flag (a device flag → exit 1 with the plain command as the hint), a device setting exactly one of `--all-devices` (scope `all`) / `--device NAME` (scope `devices` / `device`) — neither → exit 1 `KEY is a device setting: say --all-devices or --device NAME`; a key this CLI's catalog doesn't know goes to the server as typed (`unknown_setting` → 1). VALUE: `text_size` `130` or `130%` (sent as a number), `default_vault` a Vault name or id (`GET /api/v1/vaults`; unknown → exit 2) or `any`, `display_name` renames you; both print the setting's record re-read afterwards (for the Device written, else All devices — the write's own answer is resolved for the request's Device, i.e. All devices for the CLI) plus `changed` in `--json`, and `KEY unchanged` on stderr for a no-op. `devices [list] [--all]` = `ID KIND NAME LAST SEEN` (`cli/devices.rs`; LAST SEEN relative like `token list`; forgotten ones only with `--all`, NAME suffixed ` (forgotten)`), `devices rename DEVICE NAME` prints that row, `devices forget DEVICE` prints `ID NAME forgotten N Tokens revoked M sessions ended` (`--json` + `already` when it already was, with a note). DEVICE / `--device NAME` = `devices::resolve`: an exact id, else the name case-insensitively among Devices that aren't forgotten, then forgotten ones; unknown → exit 2 listing the live Devices, two with one name → exit 2 listing them. Server refusals as usual: `invalid_setting` / `low_contrast` / `bad_device` → 1, `web_device` / `device_forgotten` → 5. `Api::patch_json` is the PATCH (Device rename). `config.toml`'s top-level `device = "…"` (`Config::device`) is this install's future Device id: parsed and kept by every rewrite, written by nothing yet (no starter setting applies to kind `cli`). <!-- ---- end CMD-23 ---- -->
- <!-- ---- ticket 14 ---- --> `skill install [--dir DIR] [--force]` is a local verb (no credential, no server): writes `cli::skill::skill_md()` (the embedded SKILL.md with `metadata.version` re-pinned to `crate::VERSION`) to `DIR/annotary/SKILL.md` — DIR = `./.agents/skills` by default (the cross-harness location; `~/.claude/skills` etc. via `--dir`; DIR is always the *skills root*, one folder per skill; a literal leading `~/` is expanded) — prints `wrote PATH (vX)` / `unchanged PATH (vX)` (+ a stderr hint naming `--dir` when the default was used), refuses a differing file without `--force` (exit 5, naming the file's `metadata.version` or "edited?"), `--json {path, version, written}` (+ `dir`, `previous`). `.agents/skills/annotary/` is git-ignored at the repo root — the committed source is `crates/annotary/skill/SKILL.md`. <!-- ---- end ticket 14 ---- -->

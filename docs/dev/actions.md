# Actions & status (ticket 05 — extend, don't rewrite)

Implementation notes, moved from the root `CLAUDE.md` on 2026-10-18 (read on demand; the
index is [README.md](README.md)). Extend them with the code they describe.

- **Files:** `crates/store/src/actions.rs` (declarations, `Store::act`, the log; migration v4 = `actions` table + `documents.actions_available`, delimited `---- ticket 05 ----` in `migrations.rs`), `server/actions.rs` (route table in its header; `action_json` / `decl_json`), `cli/act.rs` (`act`, `actions`, `action_cell` / `action_record` used by `status` and `show`).
- **Declaration** = `Vec<ActionDecl {id, label, intent}>` (`ActionDecl` is `annotary_sidecar::ActionDecl`, re-exported by the store). `annotary_store::validate_declaration(&Value)` is the one rule set (kebab-case ids ≤ 39 chars, unique, never `none`; `label` defaults to the id, `intent` to `neutral`; unknown intent / bad shape ⇒ `StoreError::InvalidActions` → 400 `invalid_actions` → exit 1) — the CLI runs it in `push` before uploading, the server at commit and on `PUT …/vaults/{name}/actions`. Vault defaults live in `vaults.default_actions` (`Store::set_vault_actions`, event `vault.actions_set {vault, name, available}`, owner-only at the API); a Document's own set in `documents.actions_available` (`DocumentView.actions_available: Option<Value>`; `None` = inherited, `[]` = none) — set from `PushInput.actions_available` by `create_document` / `push_version` (also on an `already` push; event `document.actions_declared {name, available}` only when it changed; nothing sent ⇒ unchanged; there is no un-declare). `Store::available_actions(&doc) -> (Vec<ActionDecl>, inherited)` is the effective set — use it (never the Vault defaults directly) for `available_actions`, the Sidecar and any UI.
- **Taking an Action:** `Store::act(by, doc, action_id, expect_version) -> ActionView {id, label, intent, by, by_handle, at, version}` — deleted ⇒ `DocumentDeleted`, `expect_version` ≠ head ⇒ `NotHead` (409 `not_head`), id not in the effective set ⇒ `UndeclaredAction {action, available}` (409 `undeclared_action`, hint lists the ids, body carries `available[]`; exit 5). Snapshots label/intent, bumps `last_activity_at`, appends `action.taken {action, version, label, intent, name}` (`by`/`at` on the event row) — ticket 08's `wait` maps `action` onto it (`DETAIL` = `approve v5 by @rowan`). Reads: `Store::actions(doc)` (oldest first), `Store::head_action(doc, head)` (last row on the head Version — the one that counts), `Store::last_actions_all()` (one pass for `list`: a Document's last Action counts iff its `version` == head). Purge deletes `actions` rows.
- **API:** `GET /api/v1/docs/{id}/actions` → `{id, name, version, available[], inherited, action, actions[]}`; `POST …/actions {action, version?}` (`action` right) → 201 `{id, by, at, version, label, intent, doc, name}`; `GET/PUT /api/v1/vaults/{name}/actions` (`{available[]}`; PUT owner-only). `doc_json_for` fills `action` (`{id, by, at, version, label, intent}` | null) next to the Thread counts; `doc_json_full` adds `available_actions` (`[{id,label,intent}]`) + `actions_inherited`; `list` fills `action` from `last_actions_all` and honors `action=none|ID`; `status` carries the same `action` object.
- **CLI:** `act DOC ACTION [--version N]` prints `NAME\tvN\tACTION\tby @h` (TTY: two spaces), `--json {name,id,version,action,by,at}` (+`label,intent`); the CLI checks `--version` against the resolved head first (exit 5) and always sends `version: head`. `actions DOC [--deleted]` prints `ACTION BY AT VER LABEL` newest first (TTY note when empty), `--json [{id,by,at,version,label,intent}]`. `status`/`show` print `action:ID@vN by @h` | `action:-` and `--json` `action {id, by, at}` (`iso_seconds`) — build them with `cli::act::action_cell` / `action_record`. `show` still lists `actions:a,b` (ids of the effective set).
- **Sidecar:** `server/sidecar.rs::build` fills `actions {available, inherited, log[{id, by, at, version, label, intent}]}` from `available_actions` + `actions` (`action_entry`; handles, seconds; log oldest first; Action takers join `members`); the writer omits an empty `available` (a `[]` declaration with no log emits no `actions` block at all — push then sends nothing and the server keeps `[]`). `Binding` reads `actions.available` only when `inherited` is absent, and refuses an entry without `id` (`ParseError::Invalid`).

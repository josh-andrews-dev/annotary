# Web UI: commenting, Actions, keyboard, live (ticket 11 — extend, don't rewrite)

Implementation notes, moved from the root `CLAUDE.md` on 2026-10-18 (read on demand; the
index is [README.md](README.md)). Extend them with the code they describe.

- **Files:** `server/view.rs` (`Viewer {members, me, is_owner, can_comment}` decides which controls a card carries: `.cd-acts` Reply + Resolve/Reopen for anyone with `comment` on a live Document, `.cd-ctools` edit/delete for the Comment's author or an owner; `action_buttons_html` = `#cd-actbtns` on head only, one `.cd-actbtn[data-action][data-label][data-intent]` per `Store::available_actions` entry, nothing for `[]` or without the `action` right; `HELP_HTML` = `#cd-help`; `#cd-pill` only on head for commenters; `#cd-toast`; `fragment` = `GET /d/{id}/t/{tid}?v=N`), `server/ui/app.js` (everything after the "ticket 11" banner), `server/ui/app.css` (the ticket-11 block). No store / API changes; no migration.
- **`#cd-data` grew:** `me`, `me_name`, `owner`, `can_comment`, `can_act`, `deleted`, `md_hash` (the **head** Markdown blob — the script fetches `GET /api/v1/blobs/{md_hash}` once, lazily, on the first selection, to map a selection to source coordinates), `assets: [{ref, hash, type}]` (the head manifest minus `missing`, for the media pill → `ref`), `actions: [{id, label, intent}]`, `action` (the viewed Version's chip `{id, label, intent, by, at, version}` | null). The status line / `.cd-nline` / `.cd-res-n` keep ticket 10's markup; `recount()` in the script rebuilds them from the DOM after every mutation or live event — keep the two formats identical.
- **Selection → source (`mapSelection` in `app.js`):** the innermost `[data-l]` block of each selection end (climbed while the parent spans the same lines — a `td` maps through its `tr`), the rendered text of that block vs the source lines `a..=b`, aligned char by char (`align`: Markdown syntax between rendered chars is skipped, `](…)` link targets / whole `![…](…)` images / raw HTML tags jumped over, entities decoded so `&amp;` ↔ `&`), code points throughout (1-based lines, 0-based columns, half-open); the result is verified (the selection's visible chars occur in order in the source range, which starts and ends with the same characters) else the pill reports it cannot map the selection. Selections that cross a `.cd-strip` / editor are not commentable. Delimiters the selection covered on one side only are balanced (`balanceDelimiters`: `**bold** x` selected as "bold x" → `**bold** x`; "bold" alone stays `bold`; never across a word, so `snake_case` never grows). The mapped range is what the server freezes as the quote; `S11-08` pins it against `thread show`.
- **Composer / cards:** the composer is a `.cd-thread.cd-composer[data-t=newN]` appended to the strip of its first line (`stripFor(line)` — `insertionPoint`/`placeStrip` are the client twin of `splice.rs`: inside `li/td/th/blockquote/dd/dt/section`, after leaf blocks, strips at one point kept in line order; keep both in step), the selection wrapped as `mark.cd-hl.cd-pending-hl[data-t=newN]` (an Asset: `.cd-asset-hl.cd-pending-hl`). `stripFor` can return a strip hidden as `.cd-all-resolved`, when resolved Threads sit on that line, so opening and closing a composer each call `syncStripHidden` (`S36-01`); `recount` runs the same check over every strip. Posting turns it into a `.cd-pending` card immediately, `POST …/threads {subject, range|ref, body, version: head}`; success renames `newN` → the real id and `refreshCard(id)` swaps in the server's card; failure puts the composer back with the text and the error (`.cd-err`). Reply / resolve / reopen / edit / delete: `snapshot = card.cloneNode(true)` (taken after the editor is removed), the DOM changed optimistically, the API called, on failure `card.replaceWith(snapshot)` + a `.cd-err` line (and the editor back with the text); on success `refreshCard(tid)` (`GET /d/{id}/t/{tid}` — with `?v=N` on an older-Version view: the **placement as of N, the conversation live**, so a fresh reply shows on a time-slice page; `hidden` ⇒ the card is removed). An open editor survives a refresh, empty or not (CMD-13, `S25-01`): `applyFragment` marks the card `data-stale` and leaves the DOM and `D.threads` as they are; `closeEditor` (Cancel, discard, a clean `esc`) re-draws a stale card once, and posting re-draws it through the success path's `refreshCard`. Chose any open `.cd-editor`; rejected the old "editor with text" test because a refresh landing between the click on Reply and the first key closed the box under the user (the CI flake in `commenting.spec.ts`). Actions: the chip is rebuilt client-side (`setChip`) before `POST …/actions {action, version: head}`, restored on failure with a toast; `not_head` ⇒ the head-only controls go away.
- **Live feed:** `subscribe()` opens `EventSource('/api/v1/events?doc=ID&since=SEQ')` after the first layout (idle callback — never before `cd-ready`); `ready` ⇒ `.cd-app.cd-live`. Thread/Comment events for this Document ⇒ `refreshCard(thread)` (new Threads inserted at their block + highlighted; on an older-Version view only Threads already on the page); `action.taken` on the viewed Version ⇒ chip; `version.pushed` ⇒ `#cd-newver` banner ("Go to head", no navigation), `D.head` bumped, pill + Action buttons hidden, the select gains the Version; `document.actions_declared` ⇒ buttons rebuilt from `GET …/actions`. The page's own mutations come back as events too: `isEcho` (same `by`, an in-flight or just-confirmed op of that type/Thread) drops them so nothing is applied twice. History still loads on demand and prepends live events while open.
- **Keyboard** (`j k r e c [ ] ↩ ⌘↩ esc ?`, `HELP_HTML` is the list): single keys only outside fields and without ⌘/Ctrl/Alt; in a reply editor ↩ posts (⇧↩ newline), in the composer / edit editor ⌘↩ or Ctrl↩ posts; `esc` closes editor → pill → selection → overlay/panels. Adding a binding is a spec change (story 126). **`esc` never discards typed text (CMD-6, `S11-10`):** `escapeEditor` closes a clean editor immediately, but one that is dirty (`editorDirty`: the composer / a reply box with any text, an edit box whose text differs from the Comment's raw body, kept on the editor element as `cdOrig` and carried over to the editor a failed edit puts back) gets an inline `.cd-discard[role=alert]` after its textarea — "discard" (`[data-act=discard-yes]`) closes it, "keep" (`discard-no`) or `esc` again removes the confirm and puts the cursor back; the Cancel button still closes without asking. Chose an inline confirm in the card, like delete's yes/no; rejected `window.confirm` because it is modal, unstyled and blocks the live feed. `esc` acts on the editor that has focus (`closeEditor(card, editor)`), else the one showing a `.cd-discard`, else the first open one. **Opening another composer never discards typed text either (CMD-12, `S27-01`):** every way in (the pill, `c`, an inline Asset) goes through `openComposer(target)`; an empty composer is still replaced immediately, but a dirty one stays, gets the same `.cd-discard` (`askDiscard(ed, next)`, shared with `escapeEditor`) and its textarea back in focus, and the new target waits on the editor as `cdNextPending` (not in `pending`: the click on "discard" collapses the selection and `hidePill` clears it) — "discard" closes the first composer and its pending highlight and calls `openComposer(next)`; "keep" or `esc` (`keepEditing`) drops `cdNextPending`; Cancel and posting remove the editor and the stash with it; a second request while it asks replaces the stash. Chose to keep the first composer and ask; rejected opening the second beside it because one composer at a time is what the strip layout and `c` assume, and rejected moving the typed text to the new target because the text was written about the first selection.
- **Decisions to keep:** the card fragment is the only way a card is (re)drawn after load — never build card markup in JS beyond the optimistic placeholder; mutations stay on `/api/v1`; the head source is fetched lazily (not embedded, not on load); no `position: fixed` anywhere (ticket 10's "no bottom bar" test counts fixed elements — the pill/toast/help are absolute inside `.cd-app`); no literal `<details class="cd-orphaned"` / `id="cd-banner"` / `role="alert"` strings in the script (ticket 10's HTML assertions grep the whole page); resolved Threads keep hiding behind the toggle even when you just resolved them; new Threads are refused locally once a newer Version is known.

- **Keyboard settings (CMD-23):** `data-cd-keys` / `data-cd-send` on `.cd-app` (from `prefs.rs`, re-applied live), read on every keydown. **Keyboard shortcuts Off** turns off the single keys `j k r e c [ ] ?` (the `?` button still opens the help); `↩` / `⌘↩` / `esc` in editors keep working, and `app.css` hides the help's single-key rows (`tr.cd-k1`) and the pill's `c`. **Send key ⌘↩** (`mod_enter`): in a reply editor `↩` is a newline and `⌘↩` / Ctrl↩ posts; the composer and the edit box already post with `⌘↩` only, so they are the same under both values. The help's reply row is `<kbd id="cd-send-key">`, rendered with the chord by the server (`view.rs::help_html`) and rewritten by `applySettings` on a live change (one `kbd`, so the help still lists exactly the map).
- **Live:** the SSE URL gains `&me=1` and a `setting.changed` listener (see "Web UI: Document view + list", CMD-23); the Member's own setting events carry no values, so the page re-reads them.

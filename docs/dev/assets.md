# Assets (ticket 03 — extend, don't rewrite)

Implementation notes, moved from the root `CLAUDE.md` on 2026-10-18 (read on demand; the
index is [README.md](README.md)). Extend them with the code they describe.

- **Types and caps are constants**: `assets::types::SUPPORTED_TYPES` (extension → content type, kind, `scan` for Markdown, `derivative` for HEIC/HEIF/AVIF/TIFF/BMP) and `annotary_store::caps::{MARKDOWN_MAX, ASSET_MAX, VERSION_MAX}` (MiB); the CLI checks the caps before uploading with the same constants, the server enforces them at `blobs/check` (claimed sizes), `PUT /api/v1/blobs/{hash}` (streamed, capped, drained) and commit (`store/manifest.rs`, real blob sizes) as 413 `too_large` `{what, size, max}`.
- **Manifest** entries `{ref, hash, size, type, missing?, via?, width?, height?, derivative?}`: `ref` is the normalized path relative to the *root* `.md`'s directory (`assets::scan::normalize`; `via` = the `ref` of the Markdown Asset that referenced it); the server drops unknown keys, takes `size` from the blob store and refuses bad shapes with 400 `invalid_manifest`. Identity = `(ref, hash)` pairs only, so dimensions/derivatives never change a Version. Sidecar `assets[]` shows `{ref, hash, size, type, missing?, via?}` — dimensions/derivatives stay on the Version record (`GET …/versions/{n}` `manifest`).
- **Scan rules** live in `assets/scan.rs` (pure) + `assets/mod.rs` (filesystem): pulldown-cmark with `scan::MARKDOWN_OPTIONS` (the renderer must use the same options, ticket 09), so code spans/fences are not references; `.md`/`.markdown` Assets are followed to depth `assets::MAX_DEPTH` = 5 (`.txt` is not scanned), cycles by seen content hash, self-links skipped, duplicates by `ref` folded. Warnings are `assets::Warning{kind, text}` — `push` prints `warning: {text}` before uploading and `--strict` makes them one exit-5 `strict` error (first warning + `(--strict)`, or `N push warnings (--strict)` + detail lines); the JSON `warnings[]` carries them all, `assets` `{referenced, new, new_bytes, missing[]}`.
- **Media** (`assets/media.rs`): `dimensions(bytes, content_type)` (imagesize + EXIF orientation; SVG width/height/viewBox; mp4/mov `tkhd` incl. rotation; WebM EBML) and `derivative(bytes, ty)` (TIFF/BMP → PNG in-process via `image`; HEIC/HEIF/AVIF → JPEG through macOS `sips` or ImageMagick — `media::converter()`; no converter ⇒ a `Derivative` warning, push proceeds). Fixtures for all of it: `fixtures/assets/` (`make.py` regenerates them).
- **`/a/{hash}`** (`server/assets.rs`): content type from the manifest entry (`Store::asset_info` scans manifests newest-first; a derivative is sniffed PNG/JPEG), `Cache-Control: immutable`, `Content-Disposition: inline; filename=…`, `?derivative=1` serves the derivative when there is one (else the original), SVG gets a script-blocking CSP; needs `read` on some Vault (`Auth`; the browser cookie joins in 10/12). Web UI: `<img src="/a/{hash}?derivative=1" width=W height=H>` from the manifest.
- **`pull --assets`** (`cli/pull.rs`): plans every Asset file first (same hash ⇒ unchanged, differing ⇒ refuse the whole pull, exit 5, unless `--force`), writes nothing on refusal, then `.md` + Sidecar + Asset files (`out_dir.join(ref)`, dirs created; `../` refs land outside `--out`); summary `pull: N threads, M assets (K missing: …); W written, U unchanged`.

**Not an Asset:** a Member's avatar is a blob too but belongs to no Version; it has its own route, caps and SVG check (`/avatars/{hash}`, [member-settings.md](member-settings.md)). Its CSP is stricter than `/a/{hash}`'s only by naming `img-src data:`, which an SVG avatar's own `data:` images would need; the SVG check refuses those today.

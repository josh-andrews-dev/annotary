# Events, `wait`, live feed (ticket 08 — extend, don't rewrite)

Implementation notes, moved from the root `CLAUDE.md` on 2026-10-18 (read on demand; the
index is [README.md](README.md)). Extend them with the code they describe.

- **Files:** `crates/store/src/events.rs` (`EventQuery {since, until, doc_id, types, limit}` → `Store::events_page -> Vec<EventRow {event, vault_id}>` — `seq > since AND seq <= until`, oldest first, `vault_id` from a `LEFT JOIN documents` so a rights check needs no second read (None = Tenant-level event or a purged Document); `Store::comment_brief(doc, thread_num, num) -> CommentBrief {body, author, deleted}`; `Store::set_commit_hook(Option<CommitHook>)` / `fire_commit_hook`), `server/events.rs` (route table in its header; `Kind`, `classify`, `Filter`, `excerpt`, the long-poll and the SSE stream), `cli/wait.rs` (`WaitArgs`, `parse_kinds`, `parse_timeout`, `detail`, `record`, `FIELDS`). No migration: the `events` table is schema v1 and every payload already carried what `wait` prints (`version.pushed {version, name, message}`, `thread.created|replied {thread, comment?, version, mentions: [member ids]}`, `thread.resolved|reopened {thread}`, `action.taken {action, version, label, intent}`); bodies are **not** in payloads — the server quotes the Comment *as it is now* (`excerpt`; a tombstone quotes `(deleted)`) and turns `by` / `mentions` ids into handles at read time (rename-safe).
- **Waking:** `AppState::new` installs the commit hook: a `tokio::sync::watch::Sender<u64>` bumped (`send_modify`) after every committed transaction; `AppState.events` is the `Receiver`. A waiter does `rx.borrow_and_update()` → read `last_seq` → scan → if nothing, `rx.changed().await` (with the remaining timeout) → scan again — so a commit between the read and the sleep is never missed and nothing is ever held across the sleep (the store mutex is free while parked; REPORTS 01's contention note did not materialize).
- **API:** `GET /api/v1/events?since=SEQ&wait=SECS&doc=ID&kinds=a,b&action=ID&limit=N` → `{events[], seq}`: every event with `seq > since` the caller may read (`read` on the Document's Vault; Tenant-level events owner-only), oldest first; `seq` is the cursor to continue from and advances past non-matching events too (when the raw page is cut at `limit` it is the last scanned row, else the head; `since` absent or ahead of the head ⇒ the head); `wait` ≤ 30 s (clamped; 0 = answer now) parks until a *matching* event lands; `doc=` 404 unknown / 403 unreadable; `kinds=` = `wait`'s words `version,action,mention,thread,reply,resolve,reopen` (`Kind::types()` maps them to event types; `mention` = the caller's id in `payload.mentions` of `thread.created`/`thread.replied` — `comment.edited` deliberately not) or raw event types (`version.rendered`), unknown ⇒ 400; absent ⇒ every readable event (the web page's live feed / History — ticket 10 reads this, nothing else); `action=ID` narrows `action` only. Event JSON: `{seq, at, by: handle|null, type, kind: word|null, mention: bool, doc, name (current Name), vault, payload (raw), mentions: [handles]?, excerpt?}` — `kind` is `mention` only when the caller asked for mentions and it is one, else the thread/reply/… it is. **SSE:** the same URL with `Accept: text/event-stream` (an `EventSource` with the `cd_session` cookie works — `Auth` accepts it): `event: ready` `data: {seq}` first, then `id: seq` / `event: TYPE` / `data: {…}` per event as it happens, keep-alive comments while idle (`axum::response::sse`, stream built with `futures_util::stream::unfold`); `Last-Event-ID` resumes a reconnect; `wait=` ignored.
- **CLI:** `wait [DOC] [--on KINDS] [--action ID] [--cursor SEQ] [--timeout DUR]` — `--on` default `version,action,mention` (`thread,reply,resolve,reopen` opt-in; unknown ⇒ exit 1 before any request), `--timeout` default `30m` (`Ns|Nm|Nh|Nd|Nw`, `0` = never; a bare number ⇒ exit 1), `--cursor` else `status`'s `seq` (DOC) else the head; one request per ≤ 30 s (`Api::get_timeout`, per-request timeout = poll + 15 s); prints every event of the first non-empty answer as `SEQ KIND DOC DETAIL` (DOC = the Document's current Name; tab-separated, two spaces + a `wait: watching …` note on stderr on a TTY; DETAIL = `cli::wait::detail`: `v5 by @rowan "msg"` · `approve v5 by @rowan` · `t2.2 by @rowan "excerpt"` · `t9 by @rowan "excerpt"` · `t2 by @rowan`), exit 0; `--json` = one object per event *line* (`record`: `seq kind doc name action version thread comment message excerpt by at` default; `type label intent same_as mentions vault` in `all`); timeout ⇒ `CliError::wait_timeout(dur, seq)` = a **bare** error (`CliError.bare`: text mode prints the message verbatim `wait: nothing after 30m (seq 812)`, no `error:` prefix; `--json` `{error: "wait_timeout", message, seq}` via `CliError.extra`) → exit 7; unreachable mid-wait ⇒ the usual exit 6 plus a detail line `resume with --cursor N`.
- **Shutdown is bounded:** `AppState.shutdown` (a `watch<bool>`; `AppState::begin_shutdown` / `is_shutting_down`) flips the moment `server::run`'s shutdown future resolves (SIGTERM/SIGINT, or the test harness's oneshot): every parked long-poll answers immediately (`{events: [], seq}` — the client resumes from it) and every SSE stream ends (an `EventSource` reconnects with `Last-Event-ID`); axum's graceful drain then has nothing long-lived to wait for, and `server::DRAIN_MAX` (3 s) drops whatever still lingers before `server.json` is removed. Any future long-lived request must `select!` on `st.shutdown.changed()` the same way — never let a client hold the process open.
- **Decisions to keep:** the cursor is the raw `seq` (durable across restarts because it is the row id; `status` reports it); the server never blocks on the store while parked; `seq` in an empty answer still advances (so a resumed `wait` never rescans non-matching history); a future cursor heals to the head rather than erroring; Tenant-level events are owner-only on this endpoint; payloads stay body-free.

- **Access is re-checked per wake (CMD-8):** the SSE stream keeps the `AuthVia` it opened with and the commit generation (`AppState.events`) it last checked at. At the top of every turn it does `rx.borrow_and_update()`; when the generation moved it calls `Filter::refresh` → `Store::reauthenticate(via)` (read-only: no `last_used_at` / `last_seen_at` stamp and no commit hook, so a check never wakes anyone) and recomputes `readable` / `is_owner` / `handle` with `readable_vaults`. `None` (Token revoked or expired, session ended or expired, Member or Membership disabled) or a store error ⇒ the stream ends (an `EventSource` reconnects into the 401 and stops); events queued under the old access are dropped and rescanned from the last `seq` sent (`delivered`). A revoked Grant therefore silences that Vault before the next event is sent; other readable Vaults keep flowing. One check per wake, never per event — a Grant, Token, session or Member change is itself a committed transaction, so nothing can change access without moving the counter (an expiry by the clock is caught at the next wake, before anything is sent). **The long-poll** does the same: `list` takes the generation before `Filter::build` (`checked`) and, on any pass where `rx.borrow_and_update()` returns another generation (a wake, or a commit while paging a cut backlog), calls `Filter::refresh` before the rescan — a dead Credential answers 401 `unauthorized`, a revoked Grant drops that Vault from the scan; a first pass nothing committed under is not re-checked.

- **A Member's own events (CMD-23):** `setting.changed` and `device.*` carry `payload.member` and are readable by that Member only — owners included in "only" — and only on a feed that adds `me=1` (`Filter.me`; `EventQuery.member_events` ORs them into the SQL beside `doc=` / `kinds=`, and `admit` passes them whatever the kind narrowing). Their payloads carry no values. See [member-settings.md](member-settings.md).

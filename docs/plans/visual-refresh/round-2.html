Margin note, across every screen

Round 1 settled direction B (Margin note), the system sans for Documents, and a filled positive Action button (record: docs/plans/visual-refresh/record.md). This round applies B to the Document page in both appearances and both layouts, the Document list and the Settings screen, fixes what round 1's dark frames got wrong, and asks one new question: the selected card's ring. Nothing is built yet. Same real fixture data as round 1 (the seeded rfc-tile-cache RFC, the corpus Documents on the list, five Members).

  • Dark fixed: a new --cd-raise token (one step above a card) for pills and the rules inside a card; round 1 used --cd-soft, which equals the card in dark (frames 1, 2).
  • The header in one row with "2 @you" as an accent tag, the only accent in the bar (frame 1).
  • Resolved Threads get a hollow green ring instead of a filled dot, so the state is shape and color, not color alone (frame 1, Document-level card).
  • List and Settings take the same radii, pills and quiet ids (frames 4, 5).

3 · The selected card's ring pick one

The same selected card, three rings. Axis: how much the ring belongs to the tie. WCAG 1.4.11 asks a state indicator for 3:1 against its ground.

R1 A · Ink recommended

What changes. 1.5 px --cd-fg, as today's selected border.
For. 17:1 in light, 18:1 in dark; the tie carries the color.
Against. The card and its tie are two colors.

R1 B · Highlight not recommended

What changes. 2 px --cd-hl-sel: highlight, tie and ring one color.
For. The most "margin note" of the three.
Against. Yellow on white is 1.4:1: the selected state fails 1.4.11 for the default preset.

R1 C · Accent alternative

What changes. 1.5 px --cd-accent.
For. Passes (5.2:1); a touch of color.
Against. Reads as keyboard focus, which is also blue.

7 · Decisions I made

 Call
--cd-raiseOne new color token per appearance (#f1f2f5 / #2c2c2e) rather than reusing --cd-soft, which is the card color in dark.
Hollow resolved dotShape as well as color. Flagging it: it is a small change to a status everyone knows.
No markup change on the listColumn order stays (id first); only its weight drops. Reordering would move every list test for little gain.
Mentions in CommentsThe server wraps @handle of a real Member in Comment bodies (never in code), so the tag is not guessed by the script.
